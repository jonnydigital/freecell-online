## Phase 4 — Improvement shipped (1)
**a11y: label the DOM FreeCell Settings-panel close button for assistive tech.** A live accessibility scan of interactive controls (buttons / links / role=button) across the Spider spoke game page (65 controls, 0 missing names — prior toolbar fixes hold) and the FreeCell game page (110 controls, 0 missing) came back clean at the top level. Probing a deeper state — the FreeCell Settings side-panel (`DomSettingsPanel`) — surfaced one real gap: its header close (×) button (`lucide-x`, SVG `aria-hidden`) had **no accessible name**, so screen readers announced only "button". The sibling HomeOverlay close button 150 lines up already uses `aria-label={copy.close}`; the settings close was simply missed. Added `aria-label={copy.close}` to the button in `src/components/dom-freecell/DomGameShell.tsx` (line ~2661). `copy.close` is defined in all six locales (Close / Cerrar / Fermer / Schliessen / Chiudi / Fechar) and `DomSettingsPanel` already receives `copy: DomGameCopy`, so the label is localized and type-safe. Layout-neutral, no behavior change. `npx tsc --noEmit` clean; `eslint` 0 errors (445 pre-existing warnings).
