## Phase 4 — Improvement shipped (1)
**a11y: label the FreeCell landscape floating Undo/Redo buttons for assistive tech.** The recent a11y sweeps covered the desktop sub-toolbar (`SubBarBtn`, 07-26), the landscape status pill (07-22), the spoke toolbars (07-25) and the settings-panel close (07-28). Auditing the DOM FreeCell shell for the same class of gap surfaced the **landscape-only floating Undo/Redo control** (`DomGameShell.tsx` ~line 2122): two icon-only buttons (`lucide` `RotateCcw` / `RotateCw`, SVG with no text) that relied on `title=` alone for their accessible name — unreliable across screen readers. In landscape mobile these are the *only* Undo/Redo controls on screen (the portrait bottom bar is hidden via `!isLandscapeMobile`), so a screen-reader user in landscape heard only "button, button". Added `aria-label={copy.undo}` / `aria-label={copy.redo}` alongside the existing `title`. `copy.undo` / `copy.redo` are already localized across all six locales and already consumed by the same buttons' `title`, so the labels are localized and type-safe. Layout-neutral, no behavior change. `npx tsc --noEmit` clean; `eslint` **0 errors** (445 pre-existing warnings, baseline). Live re-test deferred until the deploy reaches READY (see below).
