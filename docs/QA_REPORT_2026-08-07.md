## Phase 4 — Improvements shipped

**U6 play-UX slice — post-win rating a11y correctness (`src/components/WinScreen.tsx`,
commit `53ab492`; layout-neutral, no behavior change).** The freshly-landed
post-win deal-rating widget fills its stars 1..N (`isSelected = rating <=
feedbackRating`) but set `aria-pressed` only on the exact clicked button
(`feedbackRating === rating`) — so a screen reader announced a single pressed
star while sighted users saw N filled, and the divergence would mislead about
the recorded value. Set `aria-pressed={isSelected}` so the accessible
pressed-state matches the visual fill, and added `aria-live="polite"` to the
prompt/"Thanks" status text so the post-rating confirmation is announced. No
tests reference the widget; `tsc` clean and `lint` 0 errors after the change.

One slice only: no scorecard failures, no visual bug (Spider@768 confirmed a
non-reproducible read artifact), no SEO gap (penguin `WebPage` is by-design
parity). The remaining play-UX signal (card-width tap-targets) is a
layout-sensitive U6 item that needs a planned slice, not a same-run edit.
