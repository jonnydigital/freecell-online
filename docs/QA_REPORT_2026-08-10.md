## Phase 4 — Improvement shipped (bug fix)

**`af35821` — fix(pwa): exempt service worker + manifests + offline from the
wrong-host redirect** (`src/proxy.ts`).

Root cause: `ownerOf()` defaults any unlisted path to **hub-only**
(`solitairestack`). The `proxy.ts` middleware matcher excludes image/font
extensions but **not `.js`/`.json`/no-extension routes**, and
`shouldSkipOwnershipCheck()` did not list the PWA assets. So on every **spoke**,
`/sw.js`, `/manifest.json`, `/manifest.webmanifest` and `/offline` were
**301-redirected cross-domain** to the hub.

Live evidence on playfreecellonline.com before the fix:
`navigator.serviceWorker.getRegistrations()` → **0 registrations**; `/sw.js`,
`/manifest.webmanifest` and `/offline` all returned **`opaqueredirect`**
(`/robots.txt`, which is in the skip list, correctly returned 200). A redirected
SW script is rejected by the browser, so SW registration, PWA install and the
offline fallback were silently broken off the hub — precisely the audit's
recurring console error.

Fix: add `/sw.js`, `/manifest.json`, `/manifest.webmanifest`, `/offline` to
`shouldSkipOwnershipCheck()` so they resolve same-origin on every host. The hub
(`solitairestack`) was unaffected because those paths are hub-owned there.
Layout-neutral, no route/type/locale added. `npx tsc --noEmit` clean;
`npm run lint` 0 errors / 444 warnings (unchanged from baseline). No test runner
in repo. **Post-deploy live re-verification required** (SW registers, assets
serve 200) — recorded below.
