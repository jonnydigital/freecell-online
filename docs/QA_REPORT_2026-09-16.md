## Phase 4 — Improvement: ship the 09-15 SEO/schema fix (found → confirmed live → fixed → validated → NOT shipped)

**Confirmed the bug is still live in production.** Fetched the raw HTML of the Spider
spoke homepage and counted JSON-LD `WebSite` entities: **2 WebSite nodes** on
`https://playspidersolitaireonline.com/` (should be 1). The 09-15 fix never shipped,
so every domain root still duplicates the WebSite entity.

**Root cause (unchanged from 09-15, re-verified in source):**
`src/app/(main)/layout.tsx` emits the canonical site-wide WebSite node
(`id="ld-website-site"`, with `publisher` Organization + `SearchAction`). Every
homepage rendered via `src/app/(main)/page.tsx` **also** emits its own WebSite:
- spokes (Klondike / Spider / FreeCell): `id="ld-website"` from `webSiteJsonLd`
  (SearchAction but no publisher — a strict subset of the layout node);
- hub: `id="ld-website-hub"` from `hubWebSiteJsonLd`.
Because the page renders inside the layout, **both** appear on every homepage.
Interior pages correctly show a single WebSite (layout only) — re-confirmed in Phase 3.

**Fix:** remove the redundant WebSite nodes from `src/app/(main)/page.tsx` — the
`webSiteJsonLd` const + its three spoke `<script id="ld-website">` tags, and the
`hubWebSiteJsonLd` const + its hub `<script id="ld-website-hub">` tag — keeping the
single canonical WebSite in `layout.tsx`. No behavior / layout / route / type / locale
change; the Game / WebApplication / ItemList / FAQPage nodes are untouched.

  no new warnings introduced.
