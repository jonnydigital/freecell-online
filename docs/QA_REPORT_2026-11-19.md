### One anomaly this run - self-induced Vercel rate-limit (NOT a production defect)

Running the host-side audit as a tight burst against playspidersolitaireonline.com tripped Vercel edge rate-limiting for that domain from the Mac IP: curl to the Spider domain returned HTTP 000 / timeout (curl error 28) for several minutes, while playfreecellonline.com (200 in 0.25s) and playklondikeonline.com (200 in 1.1s) stayed healthy and the Spider board rendered perfectly from the in-app browser. Connection-level drop (not a 5xx), domain-scoped to the just-hammered domain, with the board healthy via a second egress = rate-limit signature, not an outage. Full evidence + recommended mitigation: docs/analytics/mobile-viewport-audits/2026-11-19-vercel-rate-limit-during-burst-audit.md. A bullet was added to docs/AUTOMATION.md so future unattended runs do not misread this as an outage.
